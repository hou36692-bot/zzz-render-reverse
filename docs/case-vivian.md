# 案例：薇薇安选人页面与 Shader 提炼

薇薇安案例的重点有两个：先用捕获证据重建选人页面的角色、姿态和 UI，再把能出画面的实现压缩成可读、可解释的 Shader。

## 页面构成

- 角色：可编辑三维模型、实时渲染的角色层。
- 姿态与机位：从捕获数据校准；待机用 Manual Playables 和展示时钟实现冻结、寻时和重播。
- UI：uGUI + TextMeshPro 组合背景、头像卡、文字和实时角色 RenderTexture。
- 基线：比较固定在 `1.95 s` 相位，避免角色运动和相机变化掩盖 Shader 差异。

范围只覆盖当前选人页及待机，不扩展完整名册、切页演出或源游戏状态机。

## 从复刻一帧到解释渲染

早期版本能复刻部分画面，但依赖大量固定帧输入和机械转译结构。一次 Face 重写因为“代码看起来完整、实际没有解释清楚”被撤销，源码回退，用户材质等无关修改保留。

之后调整流程：

```text
反汇编 / 捕获
   → 输入与生产关系
   → 数学语义与视觉作用
   → 具名函数与可读实现
   → 单项贡献对照
   → 合并、删减、补注释
   → 最终验证
```

## FaceShader 提炼

Face 私有源码：

- 8 个文件 568 行 → 2 个文件 280 行（-50.70%）；
- 纯代码 456 → 243 行。

保留：三色边界、场景主光 / SH、用户美术调节、Stencil 发影重绘。
删除：五灯向无贡献的鼻部乘色、SourceBase 备用模式、强制角度、无调用函数和无用 varying。

验证：1.95 s 与 0.4 s 两个冻结相位，各测当前 / 前 / 左 / 右 / 背灯向、暖光与低强度光，共 14 组；脸部 800×650 裁图 RGB 最大误差 `0.00048828125`（Half 存储量级），Alpha 误差 0，超过 0.001 的像素为 0。

一次真实错误：首版精简删除了 `_FORWARD_PLUS` 变体，脸部变灰；恢复必要变体后解决。这说明引擎变体与着色数学一起构成效果，不能仅凭名字判断 keyword 冗余。

## 其余模块提炼

在 Face 通过后，按同一流程处理剩余角色渲染代码：

- Surface：控制图 / TBN 法线 → 五区域色阶 → Matcap / 高光 / 发光。
- Eye：顶点控制表 → 主图与 Alpha 遮罩 → 光照。
- Outline：平滑法线扩张 → 区域 HSV 响应。
- HairShadow：裁剪空间偏移 → Stencil 遮罩。
- 输出：亮部提取 → 单轴滤波 → 多尺度图集 → 分段响应 → 颜色合成。
- 输入：时钟、光照模式、头部轴写入实际材质槽。

删除的是死接口、重复封装、备用算法和无效写入；有实际贡献的 Matcap、高光、发光、描边、发影和输出滤波核全部保留。

代码量（同一统计范围）：

| 指标 | 提炼前 | 提炼后 |
| --- | --- | --- |
| 文件数 | 59 | 25 |
| 总行数 | 3,641 | 3,042（-16.45%） |
| 纯代码行 | 3,006 | 2,637 |

## 验证

- 四种条件（当前灯向、反向、暖光、0.4 秒待机）的整角色 1920×1080 线性 HDR Half 比较，RGB / Alpha 最大差均为 0。
- 8 个 Shader 无编译错误，C# 重编译通过。
- 退出 Play、重开场景后 `dirty=false`。
- 845 个受保护文件未变，用户材质参数保留。

这些结果证明当前条件下的输出保持，不证明所有源游戏状态或未绑定候选都已恢复。

## 与千夏的合并

2026-11-08 后，薇薇安原来的角色 Shader、Runtime 和材质 Profile 通过 `AssetDatabase.MoveAsset` 迁入统一框架，GUID 保留；两角色共享 `ZZZCharacterSurface`、`ZZZCharacterFace`、`ZZZCharacterEye`、`ZZZCharacterOutline`、`ZZZCharacterHairShadowMask` 和 `ZZZCharacterOutput`，差异只剩材质参数与骨架轴向映射。
