# 方法：从 GPU 证据到可读 Shader

本项目研究的不是“怎样让画面看起来像”，而是“这段画面由哪些输入、哪些数学步骤产生，怎样在另一个引擎里用真实输入复现同样的响应”。方法分为取证、语义、实现、验证四段。

## 1. 取证：单帧能提供什么

捕获链为 XXMI Launcher + ZZMI Frame Analysis。它导出一帧内的：

- 每次 Draw / Dispatch 的渲染状态、输入输出资源地址；
- 被引用的 Shader 快照与常量缓冲；
- 资源载荷与纹理、网格的原始数据；
- Present 记录。

它是帧级导出，不是可独立回放的 `.rdc`。这决定了后续结论必须绑定到具体构建、帧、Draw 和 Shader 身份，不能把一次成功外推到其他版本。

取证时从目标角色的最终像素所在的 Draw 出发，向上追它消费的资源和生产者，而不是全包扫描。名字、外观、文件大小只能提供线索，身份要由资源地址、原始载荷哈希和实际绑定闭合。

## 2. 证据分级

记录中始终区分四类结论：

| 级别 | 含义 | 例子 |
| --- | --- | --- |
| 已观察 | 在指定帧、Draw、Shader 中直接读到 | 某 Pass 采样某纹理、写入某 MRT |
| 已验证 | 通过受控实验确认响应或数值 | 转灯后某区域像素变化，恢复后误差为 0 |
| 推断 | 由多处证据支持但未直接闭合 | 某控制通道按区域选择色板 |
| 待补证 | 有候选解释，缺少区分实验 | 某常量是环境色还是自定义色调 |

写文档和写代码时不能把“推断”升级成“源算法”，也不能用目标侧画面接近代替源机制证明。

## 3. 从反汇编到数学语义

反汇编是证据，不是最终代码结构。每个模块先回答：

- **输入是什么？** 来自主图、控制图、顶点色、骨骼矩阵、光向、相机，还是尚未解释的缓冲量。
- **在哪个空间、哪个阶段求值？** 顶点、片元、视空间、世界空间、切线空间。
- **这段计算改变什么？** 镜像采样、明暗边界、色调权重、透明覆盖还是输出滤波。
- **怎样区分？** 改哪个输入，哪个区域应变化，哪些输出应保持不变。

最终交付是具名函数、输入契约和可区分响应实验。固定帧的矩阵、颜色、光向只作为诊断样例，不进入通用算法的默认值。

## 4. 目标侧实现

Unity 中把实现分成四层：

1. **算法核心**：与角色无关的数学，例如法线重建、色板选择、角度镜像、输出滤波。
2. **Feature**：源机制在目标引擎中的可选开关，例如贴图 V 翻转、距离色板、区域来自顶点色。
3. **角色 Profile**：材质参数、色板、骨架轴向映射。
4. **Adapter**：引擎生命周期与真实输入，例如 URP Renderer Feature、相机、骨骼绑定。

角色之间不复制整套 Shader。真正新的机制才扩展 Feature；只是参数、骨骼或材质不同时，只改 Profile。

## 5. 验证

验证分开记录，不能互相替代：

- **编译**：Shader 无错误、C# 重编译通过。
- **绑定**：材质实际指向目标 Shader，Renderer 实际消费材质。
- **数值**：合成输入下 GPU 结果与 CPU 参考逐项比较。
- **响应**：转灯、转头、改参数后目标区域变化；恢复后误差回到容差内。
- **运行**：Play 帧推进、动画输入实际写入材质槽。
- **恢复**：退出实验后材质、灯光、相机、场景状态复原；保存重开 `dirty=false`。

固定机位、固定姿态、固定画质下的像素比较只证明该条件。视觉验收由人决定，不由阈值决定。

## 6. 常见陷阱

这些坑在项目中实际发生过，也写进了案例：

- **sRGB 二次解码**：把已线性化的颜色写入 ShaderLab `Color`，在 Linear 工程上传时又解码一次。颜色属性与方向 / 直接线性量要分开。
- **导入链镜像与 V 翻转**：捕获纹理和 Unity 导入的坐标约定不同，直接采样会出现左右颠倒或上下翻转。
- **缺少 Shader 变体**：删除看似无用的 `_FORWARD_PLUS` 变体，会让主光在 Forward+ 下变成零。
- **参数变化不等于输出变化**：改时间后 GPU 蒙皮还没更新，截图会误导验证。要等真实帧推进。
- **单帧常量当默认值**：把捕获矩阵、光向、颜色写进生产 Shader，画面能接近，但换条件就崩。
- **材质恢复不完整**：实验用临时材质副本，结束时必须恢复原属性块、灯光、相机和 RT。

## 7. 资料保留原则

原始捕获、源资产字节、导出 provenance 和失败记录保留在本地研究环境，不随公开仓库分发。公开仓库只保留原创源码、方法说明和少量对照图。
